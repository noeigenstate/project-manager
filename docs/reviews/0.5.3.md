## 三位审核员的意见与处理

| 审核意见 | 需求依据 | 处理 |
| --- | --- | --- |
| SSH 目录链接和项目目录菜单隐藏启动 VS Code | 全盘取消跳转 | 返回目录结果，在内置资源管理器展开 |
| Markdown 原先只消费文件结果，目录链接会无响应 | 保留导航能力，同时移除外跳 | 复用与终端相同的链接导航处理和未保存编辑保护 |
| 远程项目内的目录软链接不能按逻辑路径展开 | 目录链接继续可用 | 使用远端已有 stat.realPath 定位实际目录，项目外路径仍拒绝 |
| 旧人工完成项目的恢复意图存在两种处理意见 | 意见绑定需求，歧义先确认 | 已向用户询问并得到明确答复：保持停止，之后手动启动 |
| 停止恢复会被误认为移除主终端，分屏项目丢失原主终端入口 | 保持停止且需要时能手动启动 | 将 primaryTerminalClosed 与 restore 分开；原有可见终端保持可见，明确关闭过的主终端不重新出现 |
| 文档仍宣传外部编辑器和人工完成 | 功能完整移除 | 同步 README、使用说明、材质说明、发布说明和协作规则 |
| Electron 44 的 writeText 返回 Promise，原路径接口没有等待；旧文件复制可能晚写覆盖路径 | 图片路径应复制为文字 | 等待原生写入；ClipboardWrites 统一提交且忽略已被新复制替代的请求，界面不显示过期成功提示 |
| 连续复制同类路径时旧成功提示仍在 | 本次写入完成后才提示成功 | 新复制开始清掉旧消息，原生测试重复同格式并暂停真实文本写入验证 |
| 分屏标题已捕获，但一次状态保存仅写到 tmp，未提交正式配置 | 保留分屏会话身份和恢复能力 | Windows EBUSY/EPERM/EACCES 原子替换最多重试 5 次，累计等待最多 100ms；最终失败明确抛错，保留原文件，不删除或直接覆盖绕过 |
| 只降低一层透明度仍会因终端/分屏/主题叠加保持磨砂 | 整体通透，不要旧磨玻璃 | 同时调整卡片、正文、分屏及主题覆盖，20px 模糊降至 1.5px |
| CSS解析成功不代表安装器内 SVG 背景折射实际有效 | 安装后的效果一致 | 截取 scale14 与 scale0 的背景边缘像素比较，另用去掉 SVG URL 的控制组测性能 |
| 边缘滤镜可能影响 fixed 定位、输入和文字 | 既有终端/展开/拖动能力保留 | 不改变布局祖先或文字 filter/opacity，只作用于背景；装饰无事件捕获，无持续 JS 动画 |

- 单元与集成测试继续覆盖通知去重、旧项目迁移、分屏可见性，并新增剪贴板顺序和 Windows 保存锁检查。
- 导航源构建桌面测试已通过：侧栏展开/收起、错误预览、SSH 根目录/嵌套目录/目录链接、Markdown 草稿取消/放弃后导航、会话保留。
